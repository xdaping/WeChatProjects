# 接入微信云开发（账号 + 管理员查看注册用户）

账号已经从「本机存储」改成「云开发」：`users` 集合存用户，`auth` 云函数处理注册 / 登录 / 改资料 / 改密码。
下面 6 步在微信开发者工具里操作，做完管理员就能在云开发控制台看到所有注册用户。

## 1. 开通云开发

开发者工具顶部工具栏 → **云开发** → 开通 →（新账号可以先选免费体验环境）→ 记下**环境 ID**（形如 `grapefruit-1a2b3c`）。

## 2. 填环境 ID

编辑 [utils/cloud-config.js](../utils/cloud-config.js)：

```js
module.exports = {
  env: 'grapefruit-1a2b3c', // ← 换成你的环境 ID
  authFunction: 'auth'
}
```

只有一个环境时也可以留空（SDK 会用默认环境），但显式写上更稳。

## 3. 建 users 集合并锁权限

云开发控制台 → **数据库** → 新建集合 `users`。

然后点集合的 **权限设置**，选 **「仅创建者可读写」以外的最严格项：所有用户不可读写（仅管理端可读写）**。
这一步很重要：`auth` 云函数是管理端身份，不受权限限制，照样能读写；而小程序前端拿不到任何用户数据，别人的邮箱和密码哈希都读不到。

（可选）给 `email` 字段建唯一索引：集合 → 索引管理 → 新建，字段 `email`、升序、勾选「唯一」。这样并发注册也不会出现同邮箱两条记录。

## 4. 建 projects / records 集合（数据同步用）

同样在 **数据库** 里再建两个集合：`projects`、`records`，权限都选 **「所有用户不可读写」**（只有云函数能读写）。

建议各加一个索引，同步会按这两个字段查：
- `projects`：字段 `userId`（升序）+ `cid`（升序），联合索引，可勾唯一
- `records`：字段 `userId`（升序）+ `cid`（升序），联合索引，可勾唯一
- 另外给两个集合各加一个 `updatedAt`（升序）索引，拉取增量时会用

## 5. 上传两个云函数

开发者工具左侧资源管理器 → 分别右键 `cloudfunctions/auth` 和 `cloudfunctions/sync` → **上传并部署：云端安装依赖（不上传 node_modules）**。

云函数只依赖 `wx-server-sdk`，密码用 Node 自带的 `crypto`（scrypt 加盐哈希），不需要本地 `npm install`。

## 6. 试一遍

小程序里：我的 → 注册 → 填邮箱 + 密码 → 提交。成功后「我的」页会显示头像和邮箱。

## 7. 管理员在哪看

云开发控制台 → **数据库 → users 集合**，一条记录就是一个注册用户：

| 字段 | 说明 |
| --- | --- |
| `_id` | 用户 ID |
| `email` | 注册邮箱（统一小写） |
| `nickName` | 昵称 |
| `avatar` | 头像（微信头像临时/永久链接） |
| `pro` | 是否高级会员 |
| `inbox` | 未读消息数 |
| `salt` / `hash` | 密码的盐与 scrypt 哈希（**看不到明文密码，这是故意的**） |
| `openids` | 已登录的微信身份，退出登录会移出 |
| `createdAt` | 注册时间 |
| `lastLoginAt` | 最近登录时间 |

控制台里可以直接搜索、筛选、改字段（比如手动给某个用户把 `pro` 改成 `true`）、导出 JSON/CSV。
云函数的调用记录和报错在 控制台 → **云函数 → auth / sync → 日志**。

`projects` 与 `records` 集合就是用户的项目和时间记录，按 `userId` 隔离：

| 字段 | 说明 |
| --- | --- |
| `userId` | 属于哪个账号（对应 users 的 `_id`） |
| `cid` | 客户端生成的稳定 id（`p_xxx` / `r_xxx`），同步就靠它对齐 |
| `updatedAt` | 最后修改时间（毫秒），冲突时**谁新用谁的** |
| `deleted` | 删除墓碑。删除不是真删记录，而是标记，这样删除才能同步到其他设备 |
| `projectCid`（records） | 这条记录属于哪个项目 |

## 忘记密码：管理员重置（不用删账号）

用户忘记密码时，**不要在数据库面板手改 `hash`** —— 密码是 scrypt 加盐算出来的，手填的值一定对不上。
`auth` 云函数里有一个管理员操作 `adminResetPassword`，靠密钥校验，不依赖 openid，可以直接在云开发控制台调用。

### 一次性配置：设置 ADMIN_KEY

1. 先生成一个随机密钥（终端里跑）：

```bash
node -e "console.log(require('crypto').randomBytes(24).toString('base64url'))"
```

2. 云开发控制台 → **云函数 → auth → 版本与配置 → 环境变量** → 添加：
   - 变量名 `ADMIN_KEY`
   - 值：上一步生成的串（**至少 16 位**，低于 16 位云函数会直接拒绝，避免弱密钥）
3. 保存。密钥只存在云函数配置里，不写进代码、不下发给客户端。

### 重置某个用户的密码

云开发控制台 → **云函数 → auth → 云端测试**，测试参数填：

```json
{
  "action": "adminResetPassword",
  "adminKey": "你的 ADMIN_KEY",
  "email": "user@example.com"
}
```

不传 `newPassword` 就自动生成一个 12 位临时密码，返回里能看到：

```json
{
  "ok": true,
  "email": "user@example.com",
  "password": "GaPJEUEcQqcs",
  "generated": true,
  "message": "已重置，把这个密码给用户，登录后请让 TA 到 设置 → 修改密码 改掉"
}
```

想指定密码就多传一个 `"newPassword": "MyTemp123"`（≥6 位）。

重置后的效果：

- 旧密码立刻失效，临时密码可以登录。
- **昵称、头像、会员状态、收件箱、注册时间全部保留**（这就是它比删账号好的地方）。
- `openids` 被清空，也就是**所有已登录设备都会掉登录态**，下次进「我的」页自动回到未登录，需要用新密码重新登录。
- 记录一个 `passwordResetAt` 时间，方便事后查。

密钥错、没配置、密钥太短、邮箱不存在、新密码太短，都会返回明确原因，不会误改数据。

### 另一种办法：删账号重注册

数据库面板里删掉那条 `users` 记录，这个邮箱就能重新注册了（唯一索引也跟着文档一起没了）。
代价是昵称、头像、会员状态、注册时间全丢；本机的项目和时间记录不受影响（它们存在手机本地，没跟账号绑定）。已登录的设备下次进「我的」页会自动掉登录态。

## 常见报错

| 提示 | 原因 |
| --- | --- |
| `auth 云函数还没上传部署` | 第 4 步没做，或函数名和 `authFunction` 不一致 |
| `云数据库还没有 users 集合` | 第 3 步没做 |
| `云数据库缺少 projects / records 集合` | 第 4 步没做 |
| `sync 云函数还没上传部署` | 第 5 步只传了 auth |
| `请先登录岁月 ID 再同步` | 当前设备没登录（数据只在本机） |
| `云开发环境未配置` | 第 2 步没填环境 ID，且账号下有多个环境 |
| `当前基础库不支持云开发` | 详情 → 本地设置里把基础库调到 2.2.3 以上 |

## 数据同步怎么工作的

本地优先，登录后双向合并：

1. **未登录**：项目和记录只写在本机（`wx.storage`），照常可用。
2. **注册/登录成功**：`sync.mergeAfterLogin()` 把同步水位归零，重扫本地全部数据上传，再把云端数据拉下来合并 —— 这就是「登录后合并上传」。
3. **平时**：任何数据改动会触发 4 秒防抖的自动同步；小程序启动、从后台回前台也各同步一次；设置页有「立即同步」。
4. **冲突**：同一条数据（`userId` + `cid`）比 `updatedAt`，谁新用谁的。
5. **删除**：本地打墓碑（`deleted: true`）再同步出去，其他设备才会跟着删。
6. **示例项目**：首次启动播的 4 个示例项目，如果一直没被编辑、也没有任何记录，就不会上传；登录后如果云端已有项目，本地这些没动过的示例会被清掉，避免换设备后重复。
7. **时间戳边界**：上传和拉取都留 1 秒重叠，避免同一毫秒内的写入被漏掉（重复传是幂等的）。
8. 计时器状态（`ih_timer`）和本机偏好（设置项）**不同步**，它们跟设备绑定。

## 还没做的事

- **没有邮箱验证码**：注册时不校验邮箱真实性，用户也不能自助找回密码（要自助找回得再接邮件服务，比如腾讯云 SES，在云函数里发信）。目前忘密码走上面的「管理员重置」。
- 登录态靠 `openids` 认设备，没有过期时间；要做「30 天免登录」这类策略得引入 token。
- 同步是全量增量拉取，没有分页游标以外的优化；数据量到几万条时应改成按项目/时间段拉取。
- 墓碑不会清理。长期使用后 `deleted: true` 的文档会累积，可以再写个定时云函数定期清理半年前的墓碑。
